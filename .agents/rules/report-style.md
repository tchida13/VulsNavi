# レポート品質・トーン＆マナー規約 (`report-style`)

`vulnavi` が出力する脆弱性対応レポート（3D HTML および 公式 A4 PDF）は、以下の品質基準を満たす必要があります。

## 1. 必須記載項目（旗印シート＆アイデアシート準拠）

1. **エグゼクティブサマリー（上司・同僚向け3行要約）**
   - 専門用語を抑え、「結局、自社システムは安全なのか？」「何件の対応を完了し、残タスクは何か？」を冒頭3行で明記する。
2. **Step 1 (CHECK): 脆弱性情報の真偽・出所判定一覧**
   - JPCERT/CC、NVD などの公的機関情報か、SNS（X等）の未確認投稿かを明示する。
   - SNS のデマ・誤情報や、既に自社で対策済みのバージョン情報については「対応不要（安全）」である根拠を明確に示す。
3. **Step 2 (APPLY / TEST): 社内システム別の該当箇所・パッチ・テスト結果**
   - 単なるライブラリ名だけでなく、**どのシステムのどのソースコード（ファイル名・行番号）で使用されているか**を明記する。
   - `requirements.txt` 等に記載があるがコード内で一切使われていない**未使用ライブラリ**は「削除推奨」として区別する。
   - 修正パッチ／バージョン更新後の**自動テスト（`unittest`）実行結果（PASS/FAIL）**と、必要に応じた**代替ライブラリの提案**を記載する。
4. **Step 3 & 4 (SUMMARY / OUTPUT): 社内複数システムへの横断影響マトリクスと今後の方針**
   - 社内保有の全システム（決済API・顧客ポータル・夜間バッチ・管理画面など）における影響有無を一覧表（マトリクス）で示し、「対応漏れがないか不安」という課題を解消する。
