# vulnavi（脆弱性レポートまとめ君）開発＆Antigravity習熟ガイド

このドキュメントは、**Antigravity Deep Dive セミナー**で作成する「脆弱性レポートまとめ君（`vulnavi`）」の開発手順と、各ステップで試すべき Antigravity の機能・コマンド・プロンプト例をまとめた実践メモです。

> 💡 **別セッションからの参照方法**
> `vulnavi` の開発セッションで `@reference/vulnavi_進め方ガイド.md` とメンションすると、このメモの内容をそのままエージェントに読み込ませて作業を進められます。

---

## 1. 企画内容の整理（アイデアシート・旗印シートより）

- **解決したい困りごと**
  - 脆弱性がたくさん見つかって対応が大変。
  - どの脆弱性がどのシステム・ライブラリに対応しているかわからない。
  - いつまで続くのか、すべて対応しきれたか不安。上司や同僚への説明・報告も手間。
- **インプット（`sample_inputs/target_project/`）**
  - `system_info.json`：対象システム（決済・注文管理バックエンド `SYS-ORD-001`）と関連システム（顧客ポータル `SYS-PORTAL-002`、夜間バッチ `SYS-BATCH-003`、管理画面 `SYS-ADM-004`）の構成情報
  - `requirements.txt`：Python 依存ライブラリ一覧（`requests`, `jinja2`, `urllib3`, `cryptography`, `pyyaml`）
  - `package.json`：Node.js 依存ライブラリ一覧（`axios`, `lodash`）
  - 脆弱性情報（CVE番号、セキュリティアドバイザリ、SNS/Webの最新情報など）
- **エージェントの作業手順（4段階）**
  1. **CHECK**：入力された脆弱性情報をもとに、情報元・内容の正しさと対象バージョンを確認
  2. **APPLY / TEST**：自身のシステムの対応箇所・修正パッチを確認し、影響範囲・テストを実施（使っていないライブラリの指摘や代替提案も含む）
  3. **まとめ**：実施した対応内容と、関連システム（`related_systems`）への影響・今後の対応方針を整理
  4. **OUTPUT**：上司や同僚にそのまま共有できる **HTML / PDF レポート** に出力

---

## 2. おすすめの進め方（5ステップ）

### Step 1：対話型で要件・設計を固める（`/grill-me` → `/plan`）
いきなりコードを書かせず、AIと仕様をすり合わせます。

- **使う機能・コマンド**
  - `/grill-me`：AIが選択式の質問を重ねて、曖昧な仕様（入力方法、レポート項目、技術スタックなど）を明確化します。
  - `/plan`：合意した仕様から実装計画（Implementation Plan）を作成します。実装前に必ずレビューで止まるため手戻りを防げます。
- **プロンプト例**
  ```text
  /grill-me @sample_inputs/target_project と @reference/スキャン_20261031-1317.pdf をもとに、脆弱性レポートまとめ君（vulnavi）のMVP仕様を詰めたいです。
  ```
- **決めておくと良いポイント**
  - 動作形態：CLIツール（Python / Node.js）か、ローカルWebアプリか
  - 脆弱性データの取得方法：OSV API（`https://api.osv.dev`）等の実APIを叩くか、デモ用の脆弱性フィード（JSON）を用意するか

---

### Step 2：MVP（最小動くもの）を作る（`@` メンション ＆ `/btw`）
まずは単一フローで、`sample_inputs/target_project` を読み込んで HTML レポートを1枚出力するプロトタイプを作ります。

- **使う機能・コマンド**
  - `@` メンション：`@sample_inputs/target_project/system_info.json` のようにファイルを直接指定してコンテキストに渡します。
  - `/btw`：エージェントがコード生成やテストを実行している最中に、作業を止めずに並行して質問や相談を投げられます。
- **プロンプト例**
  ```text
  /plan 先ほど決めた仕様で MVP を実装してください。まずは @sample_inputs/target_project の3ファイルを読み込み、脆弱性チェックから HTML レポート生成まで一気通貫で動くようにしてください。
  ```

---

### Step 3：「ソフトウェアファクトリー」化する（カスタムサブエージェント＆スキル）
MVP が動いたら、セミナー前半で紹介された **「ソフトウェアファクトリー（並列組立ライン＋品質ゲート）」** の構成へ進化させます。

- **作成するディレクトリ構成案（`vulnavi/.agents/`）**
  ```text
  vulnavi/
  └── .agents/
      ├── agents/                  # ワーカー（専門サブエージェント）
      │   ├── vuln-checker.md      # ① 情報収集・CVE妥当性確認係（CHECK）
      │   ├── patch-tester.md      # ② パッチ特定・影響範囲＆他システム波及分析係（APPLY/TEST）
      │   ├── report-writer.md     # ③ 上司・同僚向けHTML/PDFレポート作成係（OUTPUT）
      │   └── jidoka-auditor.md    # ④ 自働化（Jidoka）監査係（読み取り専用で対応漏れ・誤判定を検査）
      ├── skills/                  # ライン（標準作業手順）
      │   └── vulnavi-pipeline/
      │       └── SKILL.md         # 4つのエージェントを連携させる標準ワークフロー定義
      └── rules/                   # プロジェクト共通ルール
          └── report-style.md      # レポートの必須項目やトーン＆マナーの規約
  ```
- **プロンプト例**
  ```text
  旗印シートの作業手順（CHECK → APPLY/TEST → まとめ → レポート出力）と、読み取り専用の監査係（自働化インスペクター）を `.agents/agents/` と `.agents/skills/` に分割して、ソフトウェアファクトリー構成にしてください。
  ```

---

### Step 4：リッチな HTML レポートとブラウザ自動検証（Generative UI ＆ `/browser`）
出力されるレポートを、上司や他チーム（フロントエンドチーム・データ基盤チーム）が一目で理解できるインタラクティブUIに仕上げます。

- **使う機能・コマンド**
  - **Generative UI（`/generative-ui`）**：システム間の依存関係グラフ、深刻度バッジ、パッチ適用コマンドのコピーボタン、対応ステータス付きのダッシュボード型 HTML を生成します。
  - **`/browser`（Chrome DevTools MCP）**：生成した HTML レポートや Web UI を内蔵ブラウザで開き、表示崩れやインタラクションをエージェント自身に視覚チェックさせます。
- **盛り込むとデモ映えする要素**
  - `SYS-ORD-001`（自システム）だけでなく、`system_info.json` 内の `SYS-PORTAL-002`（`jinja2 3.1.2`, `axios 1.5.0` 共有）や `SYS-BATCH-003`（`requests 2.31.0`, `pyyaml 5.4.0` 共有）への**横展開アラート表示**
  - `SYS-ADM-004`（管理画面）がすでに `requests 2.32.2` / `jinja2 3.1.4` にパッチ適用済みであることの比較表示

---

### Step 5：知見の定着と自動化（`/learn`, `/boost`, `/schedule`）
最後に、うまくいったやり方を再利用可能にし、自動化を体験します。

- **使う機能・コマンド**
  - `/learn`：会話の中でうまくいったプロンプトや修正指示を、スキルやルール（`.agents/rules/`）として自動抽出・保存します。
  - `/boost`：複数のサブエージェントを連携させ、深い推論と検証を行ってから結果を返させます（モデル設定は Low / Flash との組み合わせが推奨）。
  - `/schedule`：「毎朝9時に `sample_inputs` の依存関係と最新CVEを照合してレポートを更新する」といった定期タスク（cron）を設定します。

## 3. よく使うコマンド・ショートカット早見表

| コマンド / 操作 | 用途・タイミング |
| :--- | :--- |
| `/grill-me` | 実装前にAIから質問してもらい、要件や仕様の抜け漏れをなくす |
| `/plan` | 実装前にステップバイステップの計画を立てさせ、レビューで一旦止める |
| `/btw` | エージェントの作業実行中に、手を止めさせず別の質問を投げる |
| `/compact` / `/context` | 会話が長くなったときに文脈を圧縮する／トークン使用量を確認する |
| `/browser` | 内蔵ブラウザで生成したアプリやHTMLレポートを開いて自動検証する |
| `/learn` | セッションで得たノウハウを `.agents/` のスキルやルールに保存する |
| `/boost` | 複雑な実装や多角的な検証をサブエージェント連携でやり切る |
| `@` | ファイル、フォルダ、過去の別セッション（Conversations）をコンテキストに渡す |
| `Option + J` / `Ctrl + K` | 承認待ちのサブエージェントへ移動（macOSは `Option`） / 承認する |
