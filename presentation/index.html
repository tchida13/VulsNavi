01 / Opening & Pitch 目安時間: 0:00 - 0:30 (30秒)
セキュリティ × ソフトウェアファクトリー（自働化）

VulNavi
（脆弱性レポートまとめ君）

脆弱性の「真偽確認・影響調査・テスト・他システム波及レポート作成」を
一気通貫で自働化するマルチエージェント・パイプライン

💡 一言でいうと：
自システムの構成情報と脆弱性情報を渡すだけで、「自分のシステムでどこを直すべきか」「他チームの関連システムに影響はないか」を調査・検証し、そのまま上司や関係部署に提出できる HTML / PDF レポートを自動生成するエージェントです。
誰のどんな困りごと？

日々大量に発表される脆弱性への対応に追われ、調査・パッチ確認・周囲への報告で疲弊している開発・運用エンジニア

インプット

① 自身の持つシステム構成・依存ライブラリ情報
② 脆弱性情報（CVE / セキュリティアドバイザリ / SNS情報）

アウトプット

今回対応した内容・検証結果・今後の対応や他システムへの影響まで網羅した HTML / PDF まとめレポート

🎤 スピーカーノート（0:00 - 0:30 / 30秒） こんにちは！私たちは脆弱性対応の調査から検証、報告レポート作成までを自働化するエージェント「VulNavi（通称：脆弱性レポートまとめ君）」を開発しました。日々流れてくる脆弱性アラートに対し、「自システムにどう影響するか」「関連する他チームのシステムは大丈夫か」を自動で調査・検証し、そのまま上司や他部署に共有できるHTML・PDFレポートを出力します。
02 / Background & Pain Points 目安時間: 0:30 - 1:15 (45秒)

なぜ「脆弱性対応」はこんなにつらいのか？

パッチを1行当てる時間より、「調査・照合・横展開確認・説明資料づくり」がエンジニアを圧迫している

1. 今の備え（現状）
🔍 ネット・SNSで手作業の情報収集
  • X (旧Twitter) やセキュリティブログ、通知メールを日々巡回して情報収集
  • 情報の真偽や深刻度（CVSSだけでなく実際の悪用条件）を1件ずつ人間が読む
  • リモートワーク主体の中、突発的なアラートで常に気が休まらない
➔
2. つらい瞬間（ボトルネック）
😵 どれがどれに対応しているか分からない
  • 複数のリポジトリ・言語（Python / Node.js 等）が混在し、該当バージョンの特定が煩雑
  • 「実は使っていないライブラリ」の調査にも同じ時間を浪費
  • 修正パッチを当てた際の影響範囲やテスト確認に手間がかかる
➔
3. 終わったあとも残る不安
😰「対応漏れはないか？」が消えない
  • 自分の担当分を直しても、「連携する別システムや夜間バッチは大丈夫か？」と不安が残る
  • 上司や他チームに「何をどう直し、どこが未対応か」を説明するレポート作成が二度手間
  • 「いつまでこのモグラ叩きが続くのか」という心理的負担

💡 解決の方向性： 1人の人間が抱え込んでいた「収集・照合・検証・報告」を、専門エージェントの組立ライン（ソフトウェア工場）に分業させる！

🎤 スピーカーノート（0:30 - 1:15 / 45秒） きっかけは、私自身の「脆弱性がたくさん見つかって対応が大変、家にいても休まらない」という切実な悩みです。 普段ネットやSNSで情報を集めていても、いざ大量の脆弱性が出ると「どのシステムのどのバージョンが該当するのか」照合するだけで一苦労です。さらに自分のシステムを直した後も、「連携する別システムに漏れはないか？」「上司や他チームへどう報告しようか？」という不安と事務作業が最後まで残ります。
03 / Solution & Agent Workflow 目安時間: 1:15 - 2:00 (45秒)

解決策：8人の代理人アイデアを「3段階のエージェントライン」に集約

アイデアシートで洗い出した8つの役割を、CHECK → APPLY/TEST → REPORT のパイプラインとして実装

▼ アイデアシート（Step 2-2）で定義した「代わりにやってほしい8人の代理人」
代理人 ①SNS等で最新の脆弱性情報・真偽を収集する人
代理人 ③自システム・リポジトリのバージョンを収集する人
代理人 ⑥使っていない不要ライブラリを指摘してくれる人
代理人 ⑤対応する修正パッチを取得・適用する人
代理人 ⑦攻撃コードも含めてテスト・検証する人
代理人 ⑧代替ライブラリや回避策を提案してくれる人
代理人 ②対応した内容を整理してレポートにまとめる人
代理人 ④上司や同僚に分かりやすく説明してくれる人
STEP 1: CHECK（調査・照合係）
🔎 情報検証 ＆ インベントリ照合

代理人①・③・⑥を統合。入力された脆弱性情報の情報元・正しさを確認し、system_info.json や requirements.txt / package.json と突合。未使用ライブラリも仕分け。

➔
STEP 2: APPLY / TEST（対策・検証係）
🛠️ パッチ特定 ＆ 影響・テスト確認

代理人⑤・⑦・⑧を統合。自システムの対応箇所を特定し、修正バージョン適用・代替案の提示・テスト検証を実施。

➔
STEP 3: REPORT（まとめ・説明係）
📊 HTML / PDF レポート出力

代理人②・④を統合。今回対応した内容に加え、今後の対応・関連する他システムへの影響有無を一覧化したレポートを生成。

🎤 スピーカーノート（1:15 - 2:00 / 45秒） この課題を解決するため、アイデア出しで書き出した「8人の代理人」を、VulNavi では3つのステップ（CHECK・APPLY/TEST・REPORT）の組立ラインに統合しました。 第1に情報元の正しさと自システム構成を照合する「CHECK」、第2に修正パッチとテストを行う「APPLY/TEST」、そして第3に他システムへの影響まで含めて上司・同僚向けにHTML/PDF化する「REPORT」です。

06 / Why Antigravity? (Software Factory Architecture) 目安時間: 3:30 - 4:30 (60秒)

Antigravity 活用ポイント：「ソフトウェア工場」としての設計

単一チャットの職人作業から、役割分担と品質ゲートを持つ「並列の組立ライン」へ

1. 専門ワーカーと標準ライン
🤖 サブエージェント ＆ スキル化
  • ワーカー（Subagents）: 「情報収集・構成照合」「パッチ検証」「レポート執筆」を独立したエージェントとして定義
  • ライン（Skills）: 誰が実行しても同じ検査基準・レポート品質になるよう標準作業手順（SOP）を SKILL.md 化
  • コンテキストの肥大化を防ぎ、複数システムを並列チェック可能
2. トヨタ式の自働化（Jidoka）
🛡️ 読み取り専用の監査ゲート
  • 単にパッチを当てるだけでなく、「情報元の真偽チェック」「他システムへの影響監査」を品質ゲートとして組み込み
  • サンドボックス環境で安全に依存関係とテストを検証
  • 人間はゼロから調べるのではなく、「検証済みレポートを承認・判断するだけ」に集中できる
3. Artifact / Generative UI
📑 成果物（レポート）で検証
  • チャットログを延々と読むのではなく、1枚の構造化された HTML / PDF レポート（Artifact）として出力
  • 非エンジニアの上司や他チームのオーナーにもそのまま共有・説明が可能
  • Webサーバー不要でどこでも閲覧でき、監査証跡としても保存可能
🧠 モデル使い分け構想:
Gemini 4 Argon / Carbon 複雑な影響範囲の推論・セキュリティ判断
➔
Gemini 3.8 Flash 各リポジトリの依存ファイル走査・高速レポート生成
🎤 スピーカーノート（3:30 - 4:30 / 60秒） 本日の Deep Dive で語られた「ソフトウェアファクトリー」の考え方をそのまま取り入れています。 1つ目は、調査・検証・レポート作成をサブエージェントとスキルに分け、誰でも同じ品質で回せる組立ラインにしたこと。 2つ目は「自働化（Jidoka）」の品質ゲートとして、情報元の真偽確認と他システムへの波及チェックを組み込んだこと。 3つ目は、チャットで終わらせず、上司や他部署にそのまま提出できる HTML/PDF の Artifact として出力する点です。
07 / Summary & Next Steps 目安時間: 4:30 - 5:00 (30秒)

まとめ：脆弱性対応を「終わらない不安」から「安心できる仕組み」へ

人間は「調査と資料作成の泥沼」から解放され、意思決定と承認だけに集中する

BEFORE（これまで）
😓 手作業のトリアージと対応漏れの不安
  • SNSやWebで手作業の情報収集、真偽確認に時間を浪費
  • 「どのシステムが該当するか」を1つずつファイル検索
  • 対応後も「別システムは大丈夫か？」と家で休まらない
  • 上司・他部署への報告資料づくりが毎回負担
AFTER（VulNavi 導入後）
✨ エージェントが調査・検証・横展開レポートまで完結
  • CHECK: 信頼できる情報源の検証と全システム構成の即時突合
  • APPLY/TEST: 修正パッチの特定・検証と不要ライブラリの棚卸し
  • REPORT: 他システムへの影響まで網羅した HTML/PDF を自動出力
  • エンジニアはレポートを見て承認・共有するだけで安心！
🚀 今後の展望（完全無人化されたセキュリティ工場へ）
⏰ スケジュール・Webhook 起動
cron や GitHub Security Alert をトリガーに夜間自動実行。朝出社したら検証済みレポートと PR が届いている状態へ。
📱 リモートコントロール承認
休日や外出先に緊急の脆弱性が出ても、スマホからレポートを確認してワンタップでパッチPRを承認。
📦 プラグイン共有
社内共通プラグインとして配布し、全チームのシステム構成を横断的に守るセキュリティ基盤へ拡張。
🎤 スピーカーノート（4:30 - 5:00 / 30秒） まとめです。VulNavi によって、これまで手作業で不安だった脆弱性対応は、調査からテスト、他システムへの影響レポート作成まで自動で回る仕組みに変わります。 今後は Antigravity のスケジュール実行や Webhook と連携させ、「朝起きたら検証済みのレポートとPRが届いていて、人間はスマホから承認するだけ」のセキュリティ工場へと進化させていきます。ご清聴ありがとうございました！
